# yesplate.app

Сайт застосунку Yes Plate. GitHub Pages віддає його звідси: гілка `main`,
корінь репозиторію, домен у `CNAME`. DNS живе в Porkbun і вказує на адреси
GitHub Pages.

## Що тут лежить

| Шлях | Що це |
|---|---|
| `index.html`, `pl/`, `en/` | головна трьома мовами |
| `dieta/`, `pl/dieta/`, `en/diet/` | чотирнадцять сторінок станів на кожну мову й перелік до них |
| `privacy/`, `terms/` | політика приватності та умови використання |
| `sitemap.xml`, `robots.txt` | карта сайту для пошуку |
| `shots/`, `og.png`, `icon.png` | знімки застосунку й картинка для месенджерів |

## Правити тут не треба

Усе, крім цього файлу, **згенероване**. Джерело лежить у головному
репозиторії застосунку:

- тексти політики й умов — `docs/*.md`;
- стани, їхні межі й рецепти — код застосунку, той самий `src/lib/safety.ts`,
  за яким страви перевіряються в телефоні;
- решта тексту сторінок і вся розмітка — `scripts/build-site.py`.

Правка просто тут переживе рівно до наступної збірки, а потім мовчки зникне.
Текст про стани ще й розійдеться з тим, що показує застосунок, — а він має
казати те саме.

## Як викласти нову версію

У головному репозиторії:

```bash
python3 scripts/build-site.py
rsync -a --exclude README.md --exclude .DS_Store site/ /шлях/до/цього/репозиторію/
```

Далі звичайні `git add -A`, `git commit`, `git push` — і **обовʼязково
відкрити живу сторінку**: GitHub Pages перезбирає не миттєво, і доки ви не
побачили зміну на `yesplate.app`, нічого не доведено.

Докладніше — `docs/site.md` у головному репозиторії.
